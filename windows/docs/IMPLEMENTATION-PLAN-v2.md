# Implementation Plan v2

상태: 구현하기로 합의했지만 v1 코드에는 아직 반영하지 않은 계획

## 목표

창 이동·크기 변경 중 UIA 탐색을 새로 시작하지 않고, 마지막으로 성공한 상대좌표로 오버레이를 계속 추적한다. 창이 안정된 뒤 해당 HWND만 다시 탐색한다.

## 확정 설계

1. 창별 UIA 작업은 HWND 단위로 분리한다.
2. 같은 HWND에 실행 중인 UIA 작업이 있으면 새 작업을 추가하지 않는다.
3. 창 이동·크기 변경 시작을 감지하면 해당 HWND의 신규 UIA 작업을 보류한다.
4. 이미 실행 중인 UIA 호출은 강제 취소하지 않는다.
5. 이동 중 UIA 결과가 반환되면 결과를 반영하지 않는다.
6. 이동 중에는 현재 HWND 좌상단과 마지막 성공 상대좌표로 오버레이만 갱신한다.
7. 이동·크기 변경 종료 후 잠시 안정화를 기다린다.
8. 안정화 후 해당 HWND에 대해서만 UIA를 1회 실행한다.
9. 작업 시작 시 HWND와 generation을 저장하고, 반환 시 현재 generation과 일치할 때만 결과를 반영한다.
10. UIA 성공 시에만 제목 표시 상태와 상대좌표를 교체한다.

## 중복 실행 처리 계획

- 이미 실행 중인 인스턴스가 있으면 종료 요청과 ACK를 주고받는다.
- ACK는 요청 접수 확인으로만 사용하며, 실제 종료 완료로 간주하지 않는다.
- ACK 이후 정상 종료와 Mutex 해제를 비동기 대기한다. 반복 타이머 polling은 사용하지 않는다.
- 정상 종료 대기 제한은 3초로 한다.
- 3초 후에도 프로세스가 남아 있으면 강제종료 여부를 사용자에게 묻는다.
- 강제종료를 선택한 경우에도 프로세스 종료와 Mutex 해제를 확인한 뒤에만 새 인스턴스를 시작한다.
- 종료 확인에 실패하면 새 인스턴스를 시작하지 않고 기존 인스턴스를 유지한다.

## 완료 조건

- 창 이동·크기 변경 중 UIA 작업이 새로 쌓이지 않는다.
- 이동 중 오버레이가 기존 상대좌표로 계속 따라온다.
- 이동 종료 후 해당 창만 재탐색된다.
- 오래된 UIA 결과가 새 상대좌표나 제목을 덮어쓰지 않는다.
- 다른 창의 UIA 결과가 대상 창에 반영되지 않는다.
